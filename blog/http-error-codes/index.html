HTTP Error Codes Explained

A complete guide to understanding status codes and what they mean for your web applications

What Are HTTP Status Codes?

HTTP status codes are three-digit numbers returned by web servers in response to client requests. They tell you the outcome of your request—whether it succeeded, needs your attention, or failed.

Think of them as a communication system between your browser (or app) and the server. Each code gives instant feedback about what happened.

⚡ Quick Reference

Range Meaning What To Do
1xx Informational Request in progress, wait for final response
2xx Success Everything worked perfectly ✓
3xx Redirection Resource moved, follow the redirect
4xx Client Error Your request has a problem, fix it
5xx Server Error Server problem, not your fault—try again later
1xx

Informational Responses

The server received your request and is processing it. You'll get a final response shortly.

100 Continue

The server has received your request headers and is ready for the body. This is intermediate—the real response is still coming.

When it occurs: Large file uploads where the client checks before sending the entire body
101 Switching Protocols

The server is switching protocols as you requested—usually from HTTP to WebSocket for real-time communication.

When it occurs: WebSocket connections, real-time chat, live notifications
2xx

Success Responses

Your request worked! The server processed it successfully and is sending you the data.

200 OK

Perfect! Your request succeeded and the server is returning the requested data. This is the happy path.

GET /api/users/123 → 200 OK (returns user data)
When it occurs: Successful GET, POST, PUT requests when everything works as expected
201 Created

Success! A new resource was created. The server typically includes the new resource's location in the response.

POST /api/users (create new user) → 201 Created
When it occurs: When you create new records in a database, upload files, add comments
204 No Content

Success! The request worked but there's no response body to send back. The action is complete.

DELETE /api/users/123 → 204 No Content
When it occurs: DELETE requests, successful form submissions with no return data
3xx

Redirection Responses

The resource has moved. Your browser automatically follows the redirect and gets the new location.

301 Moved Permanently

The resource has permanently moved to a new location. Update your bookmarks and links—this page isn't coming back.

old-domain.com/page → new-domain.com/page (301)
When it occurs: Website migrations, domain changes, old URLs that are no longer valid
302 Found (Temporary Redirect)

The resource has temporarily moved. Your browser follows the redirect, but the original URL might come back later.

GET /checkout → redirects to /login (temporarily)
When it occurs: Login redirects, temporary maintenance pages, seasonal URLs
304 Not Modified

Your cached version is still valid! The server hasn't changed anything, so use what you already have locally. Saves bandwidth.

Browser cache check → Server returns 304 (use cached version)
When it occurs: Browser caching, content not updated since last request
4xx

Client Errors

The problem is on your end—your request is malformed, incomplete, or asking for something that doesn't exist. Fix your request and try again.

400 Bad Request

The server didn't understand your request. Your syntax is wrong, data is malformed, or you're missing required fields.

POST /api/users with missing email field → 400 Bad Request
When it occurs: Invalid JSON, wrong data type, missing required parameters
401 Unauthorized

You haven't proven who you are. Authentication required. Log in or provide your credentials.

Accessing protected data without login → 401 Unauthorized
When it occurs: Missing login, expired session, missing API key
403 Forbidden

You're authenticated (logged in), but you don't have permission to access this. The server knows who you are—you just aren't allowed.

Regular user trying to delete admin data → 403 Forbidden
When it occurs: Insufficient permissions, accessing another user's private data, admin-only endpoints
404 Not Found

The resource doesn't exist. The URL is wrong, the page was deleted, or it never existed.

GET /api/users/99999 (user doesn't exist) → 404 Not Found
When it occurs: Broken links, deleted pages, typos in URLs
405 Method Not Allowed

You used the wrong HTTP method. The endpoint exists but doesn't support the method you sent (e.g., POST on a GET-only endpoint).

POST /api/users/123 (endpoint only allows GET) → 405 Method Not Allowed
When it occurs: Using POST instead of GET, DELETE on read-only endpoints
408 Request Timeout

You took too long to send the request. The server got tired waiting for you.

Slow network upload → 408 Request Timeout
When it occurs: Slow internet, hanging connections, unresponsive clients
409 Conflict

Your request conflicts with the current state of the resource. Maybe you're updating data that's been changed, or creating a duplicate.

Creating user with email that already exists → 409 Conflict
When it occurs: Duplicate entries, version conflicts in concurrent edits
410 Gone

The resource is permanently deleted and will never come back. Unlike 404, you can be certain it's gone for good.

Accessing a permanently deleted account → 410 Gone
When it occurs: Permanently deleted accounts, archived content
413 Payload Too Large

Your request body is too big. You're sending too much data. The server has a file size limit.

Uploading 1GB file to endpoint with 100MB limit → 413 Payload Too Large
When it occurs: Large file uploads, bulk data imports exceeding limits
422 Unprocessable Entity

Your request is well-formed, but the data validation failed. The syntax is correct, but the values don't make sense.

POST with email: "invalid-email" (wrong format) → 422 Unprocessable Entity
When it occurs: Validation errors, invalid data types, business logic violations
429 Too Many Requests

You're sending too many requests too fast. You've hit the rate limit. Slow down and try again later.

Making 1000 API calls in 1 second → 429 Too Many Requests
When it occurs: API rate limiting, DDoS protection, brute force prevention
5xx

Server Errors

The problem is on the server's end—your request was fine, but something went wrong internally. It's not your fault.

500 Internal Server Error

Something broke on the server. A generic "everything went wrong" message. Could be a bug, database crash, or misconfiguration.

Unhandled exception in application code → 500 Internal Server Error
When it occurs: Code crashes, database connection failures, uncaught exceptions
501 Not Implemented

The server doesn't support this feature yet. You're asking for something the server doesn't know how to do.

Using an HTTP method the server doesn't support → 501 Not Implemented
When it occurs: Unfinished features, unsupported HTTP methods
502 Bad Gateway

The server is acting as a proxy/gateway, but the upstream server gave it an invalid response. Communication breakdown between servers.

Nginx gateway → backend server crashes → 502 Bad Gateway
When it occurs: Backend server down, load balancer issues, reverse proxy misconfiguration
503 Service Unavailable

The server is temporarily unavailable—overloaded, undergoing maintenance, or temporarily down. Try again in a bit.

Server at capacity, too many requests → 503 Service Unavailable
When it occurs: Maintenance windows, server overload, temporary outages
504 Gateway Timeout

The upstream server took too long to respond. The proxy waited, but the backend server didn't answer in time.

Database query takes 10 minutes, server timeout is 30 seconds → 504 Gateway Timeout
When it occurs: Slow database queries, external API hangs, resource exhaustion

🎯 Key Takeaways

  • 1xx codes are rare and mostly transparent to you—the browser handles them automatically.
  • 2xx means success—your request worked and you got what you asked for.
  • 3xx means redirect—the resource moved, but your browser automatically follows.
  • 4xx is your fault—check your request, credentials, or data. Common ones: 404 (not found), 401 (needs login), 403 (no permission).
  • 5xx is their fault—the server has a problem. Try again later. Nothing you can do.
