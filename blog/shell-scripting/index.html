Shell scripting is the superpower of DevOps engineers. Whether you're automating deployments, managing infrastructure, processing logs, or building CI/CD pipelines — Bash is your daily toolkit. This comprehensive guide covers everything from your first shebang to production-grade automation, with real-world examples for AWS, Docker, and system administration.
01
Basics & Getting Started
Shebang, executable scripts, and script structure
1
The Shebang
First line tells system which interpreter to use
›

The shebang (#!) is a magic number that tells your OS which interpreter should execute the script. Bash is standard on Linux and macOS.

Correct Usage
#!/bin/bash

echo "Hello, World!"
echo "This runs with Bash interpreter"
First lineInterpreterMandatory
2
Make Executable
Add execute permission to run the script
›

By default, scripts aren't executable. Use chmod +x to add execute permission. Then run with ./scriptname.sh

Make Script Executable
chmod +x deploy.sh
./deploy.sh

Or run directly:
bash deploy.sh
PermissionsExecution
3
Script Structure
Professional script layout with header, variables, functions, main code
›

Good scripts follow a clear structure: header with description, variable declarations, function definitions, then main logic.

Template
#!/bin/bash
# Script: backup.sh
# Purpose: Daily backup of app data
# Author: DevOps Team

set -e # Exit on error

# Variables
BACKUP_DIR="/backups"
SOURCE="/var/app"

# Functions
log() { echo "[$(date +'%Y-%m-%d %H:%M:%S')] $1"; }

# Main
log "Starting backup"
tar -czf "$BACKUP_DIR/backup-$(date +%s).tar.gz" "$SOURCE"
log "Backup complete"
Best practicesProduction ready
02
Variables & Data Types
Store and manipulate data dynamically
1
Variable Assignment
No spaces around = sign
›

Variables store data. Assignment uses no spaces: NAME=value. Reference with $NAME. All values are strings in Bash.

Example
REGION="us-east-1"
COUNT=5
echo "Region: $REGION, Count: $COUNT"

Output:
Region: us-east-1, Count: 5
StringsNumbersNo spaces
2
Command Substitution
Capture output of a command into a variable
›

Use $(command) to run a command and store its output. This is modern syntax; backticks `command` are deprecated.

Get Current Date
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
FILE="backup-$TIMESTAMP.tar.gz"
echo $FILE

Output:
backup-20260525_143022.tar.gz
Modern syntaxdate commandAWS CLI
3
Special Variables
$0 (script name), $1-$9 (arguments), $@, $#, $$, $?
›

$0 is the script name, $1/$2 are arguments, $@ is all arguments, $# is argument count, $$ is PID, $? is exit status of last command.

Script: deploy.sh
#!/bin/bash
echo "Script: $0"
echo "Args: $@"
echo "Arg count: $#"
echo "PID: $$"

$ bash deploy.sh staging us-east-1
Script: deploy.sh
Args: staging us-east-1
Arg count: 2
PID: 12345
Positional argsExit codes
4
Environment Variables
System-wide variables like HOME, USER, PATH
›

Environment variables are inherited from the parent shell. Common ones: $HOME (user home), $USER (username), $PATH (where executables are searched).

Example
echo "Home: $HOME"
echo "User: $USER"
echo "PATH: $PATH"
echo "PWD: $PWD"

Output:
Home: /root
User: root
PATH: /usr/local/sbin:/usr/local/bin:...
System varsEnvironment
03
Operators
Arithmetic, comparison, and logical operators
1
Arithmetic Operations
Use $(( )) for math: +, -, *, /, %
›

Bash does integer arithmetic only. Use $(( expr )) syntax. Supports +, -, *, /, %, ++, --

Math Examples
A=10
B=3
echo $((A + B)) # 13
echo $((A * B)) # 30
echo $((A / B)) # 3
echo $((A % B)) # 1 (modulo)

COUNT=5
COUNT=$((COUNT + 1))
echo $COUNT # 6
Integer onlyNo spaces needed
2
Number Comparison
-eq, -ne, -lt, -le, -gt, -ge
›

Compare numbers with -eq (equal), -ne (not equal), -lt (less than), -le (less or equal), -gt (greater), -ge (greater or equal).

Examples
if [ $count -eq 0 ]; then echo "Empty"; fi
if [ $age -ge 18 ]; then echo "Adult"; fi
if [ $score -lt 100 ]; then echo "Under limit"; fi
Integers only[ ] is test command
3
File Test Operators
-e (exists), -f (file), -d (directory), -r/-w/-x (permissions)
›

Test file properties: -e (exists), -f (regular file), -d (directory), -r/-w/-x (readable/writable/executable), -s (size > 0)

Common Patterns
if [ -f "/etc/config.sh" ]; then source /etc/config.sh; fi
if [ -d "/var/log" ]; then ls /var/log; fi
if [ -x ./deploy.sh ]; then ./deploy.sh; fi
if [ -s file.txt ]; then echo "File has content"; fi
File checksCommon in scripts
4
Logical Operators
AND (&&), OR (||), NOT (!)
›

Combine conditions: && (AND) runs if previous succeeds, || (OR) runs if previous fails, ! (NOT) inverts condition.

Examples
cd /var/app && npm install && npm start

[ -f config.json ] || cp config.default.json config.json

[ ! -f /root/.ssh/id_rsa ] && ssh-keygen -t rsa
Control flowError handling
04
Conditionals
if/elif/else and case statements
1
if/elif/else
Execute code based on conditions
›

Use if/then/fi for single condition, elif for multiple, else for fallback. Note: 'fi' ends the statement (if backwards).

Three-way Example
if [ $status = "running" ]; then
echo "Service is running"
elif [ $status = "stopped" ]; then
echo "Service is stopped"
else
echo "Service status unknown"
fi
Most commonReadable
2
case Statement
Cleaner alternative to multiple if/elif
›

case is cleaner than many if/elif blocks. Pattern matching with * as wildcard. Ends with 'esac' (case backwards).

Environment-based Logic
case $ENV in
production)
REPLICAS=3
;;
staging)
REPLICAS=2
;;
*)
REPLICAS=1
;;
esac
Pattern matchingCleaner code
3
Nested Conditions
if inside if for complex logic
›

You can nest if statements. Better to use && or || operators for readability in most cases.

Example
if [ -f "/var/lock/deploy.lock" ]; then
if [ $USER = "root" ]; then
echo "Deployment in progress by root"
fi
fi

# Better:
[ -f "/var/lock/deploy.lock" ] && [ $USER = "root" ] && echo "Deploying"
Control flowReadability
05
Loops
for, while, and until loops
1
for Loop (Range & List)
Iterate over numbers or items
›

for loops iterate over a range {1..5}, a list (apple banana), or files. Syntax: for VAR in LIST; do ... done

Three Patterns
# Range
for i in {1..3}; do echo $i; done

# List
for env in dev staging prod; do
echo "Deploying to $env"
done

# Files
for file in *.log; do
gzip "$file"
done
RangeFilesMost common
2
for Loop (C-style)
Traditional format with init; condition; increment
›

C-style for loop: for ((init; condition; increment)). Double parentheses needed. Good when you need step size.

Examples
# Count 0 to 9
for ((i=0; i<10; i++)); do
echo $i
done

# Every 2nd number
for ((i=0; i<10; i+=2)); do
echo $i # 0, 2, 4, 6, 8
done
IncrementFamiliar to C programmers
3
while Loop
Loop while condition is true
›

while runs as long as the condition is true. Exit when condition becomes false. Useful for reading lines from files.

Examples
# Counter
COUNT=1
while [ $COUNT -le 3 ]; do
echo $COUNT
COUNT=$((COUNT + 1))
done

# Read file
while IFS= read -r line; do
echo "Processing: $line"
done < config.txt
File readingInput processing
4
until Loop
Loop until condition becomes true (opposite of while)
›

until is the opposite of while. Runs while condition is FALSE, stops when true. Less common but useful for wait loops.

Wait for Service
# Wait until server is up
until [ $count -gt 30 ]; do
if curl -s http://localhost:8080 > /dev/null; then
echo "Server is ready"
break
fi
count=$((count + 1))
sleep 1
done
WaitingHealth checks
5
Loop Control
break (exit) and continue (skip to next iteration)
›

break exits the loop completely. continue skips the rest of current iteration and starts next. Essential for complex loop logic.

Examples
# Stop at first error
for file in *.txt; do
[ ! -r "$file" ] && break
process_file "$file"
done

# Skip empty lines
while IFS= read -r line; do
[ -z "$line" ] && continue
echo "Non-empty: $line"
done < file.txt

06
Functions
Reusable code blocks with parameters and return values
1
Define a Function
function_name() { ... } or function function_name { ... }
›

Functions group related commands. Two syntaxes work: function_name() or function function_name. The first is preferred (POSIX compliant).

Define & Call
greet() {
echo "Hello, World!"
}

greet # Call the function

Output:
Hello, World!
ReusabilityPOSIX
2
Function Parameters
$1, $2 for arguments; $@, $# for all args and count
›

Functions receive arguments just like scripts: $1 is first arg, $2 is second, $@ is all, $# is count. $0 inside a function is the function name.

Deploy Function
deploy() {
ENV=$1
REGION=$2
echo "Deploying to $ENV in $REGION"
echo "All args: $@"
echo "Arg count: $#"
}

deploy staging us-east-1

Output:
Deploying to staging in us-east-1
All args: staging us-east-1
Arg count: 2
ArgumentsFlexible
3
Return Values
echo for output, return for exit code, $(...) to capture
›

Functions can return data via echo (captured with $(...)) or return exit code (0=success, 1=failure). Both are used.

Examples
add() {
echo $(($1 + $2))
}

result=$(add 5 3)
echo "5 + 3 = $result" # 5 + 3 = 8

is_file_readable() {
[ -r "$1" ] && return 0 || return 1
}

if is_file_readable "/etc/passwd"; then
echo "Readable"
fi
Output captureExit codes
4
Local Variables
Scope with 'local' keyword inside functions
›

By default, variables are global. Use 'local' inside functions to limit scope. Prevents accidental overwrites of global state.

Scope Example
GLOBAL="I'm global"

my_function() {
local LOCAL="I'm local"
GLOBAL="Modified"
echo "Inside: GLOBAL=$GLOBAL, LOCAL=$LOCAL"
}

my_function
echo "Outside: GLOBAL=$GLOBAL"
echo "Outside: LOCAL=$LOCAL" # Empty

Output:
Inside: GLOBAL=Modified, LOCAL=I'm local
Outside: GLOBAL=Modified
Outside: LOCAL=
ScopeBest practice

Advanced Topics
Arrays, text processing, sed/awk, cron jobs, debugging
1
Arrays
Store multiple values in one variable
›

Arrays store multiple values. Syntax: ARRAY=(item1 item2). Access with ${ARRAY[0]}, ${ARRAY[@]} for all, ${#ARRAY[@]} for length.

Array Operations
REGIONS=(us-east-1 us-west-2 eu-west-1)

echo ${REGIONS[0]} # us-east-1
echo ${REGIONS[@]} # All items
echo ${#REGIONS[@]} # 3

for region in ${REGIONS[@]}; do
echo "Processing $region"
done
Multiple valuesIteration
2
sed - Stream Editor
Text substitution and manipulation
›

sed is powerful for text transformation. s/old/new/ replaces, g flag does global replacement, d deletes lines. Essential for config file updates.

Real-world Examples
# Replace first match on each line
sed 's/localhost/127.0.0.1/' config.txt

# Replace all matches (g flag)
sed 's/foo/bar/g' file.txt

# Delete empty lines
sed '/^$/d' file.txt

# Update config in-place
sed -i 's/OLD_VAL/NEW_VAL/g' /etc/config.conf
Text transformConfig updates
3
awk - Text Processing
Extract columns, filter rows, aggregate data
›

awk is a full programming language for text. $1, $2 are fields. Use for log parsing, CSV extraction, and data aggregation in production systems.

Log Analysis Examples
# Extract IP and status from Apache log
awk '{print $1, $9}' access.log

# Count requests per IP
awk '{print $1}' access.log | sort | uniq -c

# Sum column 2
awk '{sum += $2} END {print "Total: " sum}' data.txt

# Filter lines where status > 400
awk '$9 > 400 {print $0}' access.log
Log parsingCSV processing
4
Error Handling
Exit on error, undefined variables, pipeline failures
›

Use 'set -e' to exit on error, 'set -u' for undefined var error, 'set -o pipefail' for pipeline failures. Production scripts must use these!

Safe Script Template
#!/bin/bash
set -euo pipefail

# Now script exits if:
# - Any command fails (-e)
# - Undefined variable used (-u)
# - Pipe command fails (pipefail)

echo "Starting safe deploy"
cd /opt/app || exit 1
npm install
npm run build
npm start
Production readySafety
5
Cron Jobs
Schedule scripts to run automatically
›

crontab -e edits scheduled jobs. Format: minute hour day month dayofweek command. Essential for backups, health checks, cleanup tasks.

Cron Examples
# Every day at 2:00 AM
0 2 * * * /opt/scripts/backup.sh

# Every 6 hours
0 */6 * * * /opt/scripts/health-check.sh

# Every Monday at 9 AM
0 9 * * 1 /opt/scripts/deploy.sh

# Every 15 minutes
*/15 * * * * /opt/scripts/monitor.sh

# View cron logs
grep CRON /var/log/syslog
SchedulingAutomation
6
Debugging
bash -x to trace execution, set -x for parts of script
›

bash -x runs script in debug mode, printing each command before execution. set -x enables in middle of script. Use for troubleshooting failures.

Debug Methods
# Run entire script in debug
bash -x deploy.sh

# Or in script:
#!/bin/bash
set -x # Enable debug from here
cd /var/app
npm install
set +x # Disable debug
