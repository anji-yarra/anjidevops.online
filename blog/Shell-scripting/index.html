Getting Started
Shebang, executable scripts, and basic structure
Shebang
The First Line
Tells the OS which interpreter to use
›

Always start your script with #!/bin/bash. This shebang tells Linux to execute the file using the Bash interpreter. Without it, the OS won't know how to run it.

Example
#!/bin/bash
# This is a comment
echo "Hello, World!"
EssentialFirst lineInterpreter
Execute
Make Script Executable
Add execute permission so you can run it
›

Files aren't executable by default. Use chmod +x to grant execute permission. Then run with ./script.sh (the ./ means current directory).

Commands
chmod +x hello.sh
./hello.sh

# Output: Hello, World!
PermissionschmodRun
Echo
Print Output
Display text or variable values
›

Echo prints text to the terminal. Use quotes for strings, and $ to reference variables. Essential for debugging and user feedback.

Examples
echo "Hello"
NAME="Anji"
echo "Hello, $NAME"
echo $((10 + 5))

Variables & Data
Store and use information in your scripts
Assign
Create a Variable
No spaces around the = sign
›

Variables store data. Use no spaces around =. When reading, prefix with $. Variable names are case-sensitive and cannot contain spaces or start with numbers.

Examples
REGION="ap-south-1"
COUNT=5
IS_PROD=true
echo $REGION # ap-south-1
AssignmentStringsNumbers
Capture
Command Substitution
Save a command's output into a variable
›

Use $(command) to run a command and capture its output. This is how you store results like the current date, user, or file listings.

Examples
NOW=$(date)
HOSTNAME=$(hostname)
USER=$(whoami)
echo "User: $USER, Time: $NOW"

Args
Script Arguments
Access parameters passed to your script
›

Scripts receive arguments from the command line. $1 is the first argument, $2 the second, etc. $# gives total count, $@ gives all arguments as a list.

Script: deploy.sh
#!/bin/bash
REGION=$1
ENV=$2
echo "Deploying to $REGION ($ENV)"

# Run: ./deploy.sh us-east-1 prod

Env
Environment Variables
Pre-set by the system for common values
›

The system pre-defines common variables like $HOME (user's directory), $USER (current user), $PWD (current working directory), $PATH (where executables live).

Examples
echo $HOME # /home/anji
echo $USER # anji
echo $PWD # /var/www
echo $HOSTNAME # prod-server-01

Operators
Arithmetic, comparison, and logical operations
Math
Arithmetic
Do math with numbers
›

Use $(( )) for arithmetic. Supports +, -, *, /, and % (modulo). Always returns integers—no decimals.

Examples
echo $((10 + 5)) # 15
echo $((20 - 3)) # 17
echo $((4 * 6)) # 24
echo $((15 / 3)) # 5
echo $((17 % 5)) # 2

Compare
Number Comparison
Compare two numbers: -eq, -ne, -lt, -gt, -le, -ge
›

Use [ ] (square brackets with spaces) and special operators. Not standard < and >. Note the spaces: [ $A -gt $B ] is correct, [$A-gt$B] fails.

Examples
[ 10 -eq 10 ] # true
[ 5 -lt 10 ] # true
[ 20 -gt 15 ] # true
[ 5 -ne 5 ] # false
-eq = equal-ne = not equal-lt = less than-gt = greater than
Files
File Tests
Check if file exists, is readable, is directory, etc
›

Test properties of files. -e (exists), -f (is regular file), -d (is directory), -r (readable), -w (writable), -x (executable), -s (has content).

Examples
[ -f /etc/passwd ] # true (file exists)
[ -d /var/log ] # true (directory exists)
[ -x /usr/bin/bash ] # true (executable)
[ -s config.sh ] # true (has content)
-e exists-f file-d directory-r readable-x executable
Logic
Logical Operators
AND (&&), OR (||), NOT (!)
›

Combine conditions. && = AND (both must be true), || = OR (either can be true), ! = NOT (reverse the result).

Examples
[ $age -gt 18 ] && echo "Adult"
[ $status = "ok" ] || echo "Error!"
[ ! -f file.txt ] && echo "Not found"
[ -f config.sh ] && [ -x config.sh ] && ./config.sh
ANDORNOTConditions

Control Flow
if/else, loops, and decision making
If
Conditional Statement
Run code only if a condition is true
›

The foundation of control flow. Semicolons separate commands on the same line. 'then' and 'fi' are required (fi = end if, backwards).

Example
if [ $status = "ok" ]; then
echo "All good"
exit 0
fi
Conditionalthenfi = end
Elif
Multiple Branches
Check multiple conditions in sequence
›

elif = "else if". Chain multiple conditions. Only the first matching branch executes. This is cleaner than nested ifs.

Example
if [ $REGION = "us-east-1" ]; then
COST=10
elif [ $REGION = "ap-south-1" ]; then
COST=5
else
COST=15
fi
Multiple conditionselif = else ifCleaner code
For
Loop Over Items
Repeat code for each item in a list
›

Loop through a range of values, list of items, or files. Three styles: 'in list', 'in {range}', or C-style. 'do' and 'done' enclose the loop body.

Examples
for i in {1..5}; do
echo "Number: $i"
done

for instance in prod-1 prod-2 prod-3; do
aws ec2 describe-instances --filters "Name=tag:Name,Values=$instance"
done
ListsRangesIteration
While
Loop While Condition True
Keep looping until the condition becomes false
›

Looping based on a condition rather than a list. Keep executing while the condition is true. Be careful of infinite loops!

Example
COUNT=1
while [ $COUNT -le 5 ]; do
echo "Count: $COUNT"
COUNT=$((COUNT + 1))
done

Case
Switch Statement
Match a value against multiple patterns
›

Cleaner than multiple if/elif/else. Each pattern is followed by ). The ;; ends each case. * is the default catch-all.

Example
case $ENV in
prod) TIMEOUT=30 ;;
staging) TIMEOUT=15 ;;
dev|local) TIMEOUT=5 ;;
*) echo "Unknown environment"; exit 1 ;;
esac
SwitchPattern matchingCleaner than elif* = default

Functions
Reusable code blocks with parameters and returns
Define
Create a Function
Define code once, call it many times
›

Functions group code for reuse. Define first, call by name later. The { and } enclose the body. Must define before calling.

Example
greet() {
echo "Hello, World!"
}

greet # Call the function
Code reuseDefine onceCall many
Params
Function Parameters
Pass data into functions
›

Functions receive parameters like scripts do. $1 is first parameter, $2 is second, etc. Pass them as space-separated values when calling.

Example
deploy() {
REGION=$1
ENV=$2
echo "Deploying to $REGION ($ENV)"
}

deploy "us-east-1" "prod"
Arguments$1 $2Pass data
Return
Return Values
Exit code: 0 = success, non-zero = error
›

Functions return an exit code (0-255). 0 means success, anything else means failure. Check with $? after calling. Use echo to return text output.

Example
deploy() {
[[ -f /etc/deployed ]] || return 1
echo "Success"
return 0
}

deploy && echo "Deployed OK" || echo "Failed"
Exit code0 = successNon-zero = error
Local
Local Variables
Variables scoped to function only
›

Use 'local' to limit variable scope to the function. Without it, variables are global. Best practice: use local for function-internal data.

Example
configure() {
local TIMEOUT=30 # Only in this function
REGION="us-east-1" # Global
}
configure
echo $TIMEOUT # Empty (local, not set outside)
echo $REGION # us-east-1 (global)

Advanced Topics
Arrays, text processing, error handling, automation
Arrays
Store Multiple Values
Lists of data in one variable
›

Arrays store multiple values. Access with ${ARRAY[index]} (0-indexed). ${ARRAY[@]} gets all elements. ${#ARRAY[@]} gets length.

Example
REGIONS=(us-east-1 ap-south-1 eu-west-1)
echo ${REGIONS[0]} # us-east-1
echo ${REGIONS[@]} # All items
echo ${#REGIONS[@]} # 3

for r in ${REGIONS[@]}; do
echo "Region: $r"
done
Lists0-indexedIteration
Text
Text Processing
sed (search/replace), awk (columns/data)
›

sed streams and edits text (replace patterns). awk extracts columns and processes data. Both are extremely powerful for log parsing and data transformation.

Examples
# sed: replace old with new
cat app.log | sed 's/ERROR/CRITICAL/g'

# awk: print columns
ps aux | awk '{print $1, $11}'

# awk: sum column
awk '{sum += $2} END {print sum}' data.txt

Error
Error Handling
Exit immediately if any command fails
›

'set -e' stops script execution if any command returns non-zero. Critical for production scripts—one failure stops the chain reaction. Also use -u (error on undefined vars) and -o pipefail (pipe errors).

Example
#!/bin/bash
set -e # Exit if anything fails
set -u # Error on undefined variables
set -o pipefail # Pipe failures matter

cd /var/www || exit 1
npm install
npm run build # If fails, script stops
