The Shebang
Tells the system which interpreter to use for this script
›

The shebang (#!) is the first line of every script. It specifies the interpreter. Always use #!/bin/bash for maximum compatibility on Linux/Mac systems.

Example
#!/bin/bash # Your script starts here echo "Hello, World!"
MandatoryFirst lineBash compatible
chmod +x
Making Scripts Executable
Add execute permission so you can run the script
›

Without execute permission, you can't run a script directly. chmod +x adds execute permission for all users. Then use ./scriptname.sh to run it from the current directory.

Commands
chmod +x hello.sh ./hello.sh # Runs the script bash hello.sh # Also works (runs explicitly with bash)
PermissionschmodExecutable

Your First Script
Print text to the terminal — the hello world of bash
›

echo outputs text to stdout. It's the most basic command. Every string you want to print to the terminal goes through echo.

Example Script
#!/bin/bash echo "Welcome to Shell Scripting" echo "This is line 2"

Comments
Document your code — lines that don't execute
›

Comments start with # and are ignored by the interpreter. Always add comments explaining the purpose of your script and complex sections. The only exception: #!/bin/bash is a comment that doubles as a directive.

Good Comments
#!/bin/bash # Backup script for production database # Author: Anji Yarra # Date: May 2026 # Connect to RDS instance DB_HOST="prod-db.region.rds.amazonaws.com"

Variable Assignment
Create a variable and store a value — no $ when assigning
›

Variables store values. To assign: NAME=value (no spaces). To use: $NAME. Common mistake: using $ on the left side of assignment — always wrong.

Correct vs Wrong
✓ NAME="Alice" # Correct ✗ $NAME="Alice" # Wrong ✗ NAME = "Alice" # Wrong (spaces)

Using Variables
Access the value stored in a variable with $
›

Prefix the variable name with $ to access its value. Without $, bash treats it as literal text. Always quote variables in echo to avoid word splitting.

Example
NAME="Cloud Engineer" echo $NAME # Cloud Engineer echo "$NAME is AWS certified" # Cloud Engineer is AWS certified

Command Substitution
Save the output of a command into a variable
›

Use $(command) to run a command and capture its output. Modern syntax is $(). Old backtick syntax `command` still works but is discouraged.

Example
CURRENT_USER=$(whoami) TODAY=$(date +%Y-%m-%d) echo "User $CURRENT_USER logged in on $TODAY"

Special Variables
Bash provides variables with automatic values
›

Bash automatically sets variables: $0=script name, $1=$2=$3=arguments, $#=number of arguments, $?=exit code of last command, $$=process ID.

Example Script
#!/bin/bash echo "Script: $0" echo "First arg: $1" echo "Total args: $#" echo "Last exit code: $?"

Arithmetic, comparison, logical, file tests
$((...))
Arithmetic Operations
Do math: +, -, *, /, %
›

Use $(( )) for arithmetic. Inside the double parentheses, you don't need $ for variables. Supports: +, -, *, /, % (modulo), ++, --.

Examples
A=10 B=3 echo $((A + B)) # 13 echo $((A * B)) # 30 echo $((A / B)) # 3 echo $((A % B)) # 1
MathDouble parensNo $

Number Comparison
Compare: -eq, -ne, -lt, -le, -gt, -ge
›

Compare numbers with test operators inside [ ]. Don't use = or <: they're for strings. Use -eq for "equal to", -lt for "less than", etc.

Comparison Operators
[ $A -eq $B ] # Equal to [ $A -ne $B ] # Not equal [ $A -lt $B ] # Less than [ $A -le $B ] # Less or equal [ $A -gt $B ] # Greater than [ $A -ge $B ] # Greater or equal
Numbers onlySquare bracketsTest command

File Tests
Check: file exists, is directory, readable, writable
›

Test file properties: -e (exists), -f (is file), -d (is directory), -r (readable), -w (writable), -x (executable), -s (non-empty).

Example
if [ -f "config.json" ]; then echo "Config file exists" fi if [ -d "/var/log" ]; then echo "Log directory found" fi

Logical Operators
AND, OR, NOT — combine conditions
›

AND (&&): both must be true. OR (||): at least one true. NOT (!): negates the condition.

Examples
[ $AGE -gt 18 ] && echo "Adult" [ -f "file.txt" ] || echo "File missing" [ ! -d "/tmp" ] && echo "/tmp doesn't exist"

if/else Conditionals
Execute code based on conditions
›

if tests a condition. If true, execute the then block. Use elif for multiple branches, else for the fallback. Always end with fi.

Example
if [ $AGE -ge 18 ]; then echo "Adult" elif [ $AGE -ge 13 ]; then echo "Teenager" else echo "Child" fi

for Loops
Iterate over ranges, lists, or files
›

for loops iterate. Common syntaxes: for i in {1..10}, for item in list, for ((i=0; i<10; i++)). Always end with done.

Examples
for i in {1..5}; do echo "Number: $i" done for file in *.log; do echo "Processing $file" done

while Loops
Loop while condition is true
›

while loops run as long as condition is true. Common for reading files or processing data. Always ensure the condition eventually becomes false to avoid infinite loops.

Example
COUNT=1 while [ $COUNT -le 5 ]; do echo "Count: $COUNT" COUNT=$((COUNT + 1)) done

case Statements
Switch on value — cleaner than multiple if/elif
›

case evaluates a value against patterns. Cleaner than if-elif-else when checking one variable against many values. Each pattern ends with ;;.

Example
case $DAY in Monday) echo "Start of week" ;; Friday) echo "TGIF" ;; Saturday|Sunday) echo "Weekend" ;; *) echo "Weekday" ;; esac

›

Arrays store lists. Create with (space-separated values). Access with ${array[index]}. Use ${#array[@]} for length and ${array[@]} for all elements.

sed — Stream Editor
Powerful text replacement and manipulation
›

sed modifies text. Common use: sed 's/old/new/g' replaces all occurrences of "old" with "new" in a file. The g flag means "global" (all on each line).

Examples

awk — Column Processing
Extract and process columns from text
›

awk processes text in columns. Use $1, $2, etc. for columns. Common: awk '{print $1, $3}' shows columns 1 and 3. Perfect for parsing log files.

Examples
awk '{print $1}' access.log # 1st column awk '{sum += $2} END {print sum}' data.txt # Sum column 2 awk -F: '{print $1}' /etc/passwd # Parse /etc/passwd

Error Handling
Make scripts fail fast on errors
›

set -e makes the script exit if any command fails. set -u errors on undefined variables. set -o pipefail exits if any pipe fails. Add these at the top for robust scripts.

Best Practice
#!/bin/bash set -e # Exit on error set -u # Error on undefined vars set -o pipefail # Pipe failures exit script # Rest of script...

Number Comparison
Compare two numbers: -eq, -ne, -lt, -gt, -le, -ge
›

Use [ ] (square brackets with spaces) and special operators. Not standard < and >. Note the spaces: [ $A -gt $B ] is correct, [$A-gt$B] fails.

Return Values
Exit code: 0 = success, non-zero = error
›

Functions return an exit code (0-255). 0 means success, anything else means failure. Check with $? after calling. Use echo to return text output.

Example
deploy() {
[[ -f /etc/deployed ]] || return 1
echo "Success"
return 0
}

deploy && echo "Deployed OK" || echo "Failed"

Local Variables
Variables scoped to function only
›

Use 'local' to limit variable scope to the function. Without it, variables are global. Best practice: use local for function-internal data.

Example

}
configure
echo $TIMEOUT # Empty (local, not set outside)
echo $REGION # us-east-1 (global)

sed streams and edits text (replace patterns). awk extracts columns and processes data. Both are extremely powerful for log parsing and data transformation.

Error
Error Handling
Exit immediately if any command fails
›

'set -e' stops script execution if any command returns non-zero. Critical for production scripts—one failure stops the chain reaction. Also use -u (error on undefined vars) and -o pipefail (pipe errors).

Example
#!/bin/bash
set -e # Exit if anything fails
set -u # Error on undefined variables
set -o pipefail # Pipe failures matter

cd /var/www || exit 1
npm install
npm run build # If fails, script stops
